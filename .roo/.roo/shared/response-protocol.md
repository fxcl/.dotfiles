# Response Protocol

Standard response protocol ensuring consistent interaction experience and high-quality output.

## Core Response Process

| Step | Objective | Key Activities |
|------|-----------|----------------|
| **Analysis** | Understand Requirements | Parse user intent, identify task type, assess complexity |
| **Tool Selection** | Choose Methods | Determine optimal tools, plan execution order, estimate resource needs |
| **Execution** | Implement Solution | Execute according to plan, monitor progress, handle exceptions |
| **Validation** | Ensure Quality | Result verification, quality checks, user confirmation |

## Response Structure Template

```
### Task Analysis
- Requirements Understanding: [Brief description of user needs]
- Complexity Assessment: [Simple/Medium/Complex]
- Expected Results: [Clear deliverables]

### Execution Plan
1. [Specific step 1]
2. [Specific step 2]
3. [Specific step 3]

### Implementation Results
- Completion Status: [Completed/Partially Completed/Needs Adjustment]
- Key Outputs: [List main deliverables]
- Validation Results: [Quality check results]

### Follow-up Recommendations
- [Next action suggestions]
```

### Security Mode

## Error Handling Protocol

### Error Classification

- **Minor Errors**: Auto-fix, continue execution
- **Medium Errors**: Prompt user, request confirmation
- **Critical Errors**: Stop execution, detailed reporting

### Error Report Format

```
Error Type: [Classification]
Error Description: [Specific issue]
Impact Scope: [Affected components]
Recommended Solution: [Resolution suggestions]
```

## Quality Assurance

### Output Standards

- Accuracy: Information is correct and error-free
- Completeness: Covers all requirements
- Clarity: Clear and concise expression
- Actionability: Provides specific steps

### Validation Checkpoints

- [ ] Requirements fully satisfied
- [ ] Code syntax correct
- [ ] Tests pass
- [ ] Documentation complete
- [ ] Security compliant
